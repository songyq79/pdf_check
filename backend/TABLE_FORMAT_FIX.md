# Word 表格格式错误修复

## 修复日期
2026-03-03

## 问题描述
错别字检查完成后，下载文档，首页表格内的文字错版，未与其他行对齐，并且表格线位置不对。

## 根本原因
`_write_revision()` 函数在重建段落内容时，没有确保 `w:pPr`（段落属性）始终在段落的最前面。

根据 Word OOXML 规范，段落的 XML 结构必须是：
```xml
<w:p>
    <w:pPr><!-- 段落属性，必须在最前面 --></w:pPr>
    <w:r><!-- 文字运行 --></w:r>
    <w:del><!-- 删除修订 --></w:del>
    <w:ins><!-- 插入修订 --></w:ins>
</w:p>
```

如果 `w:pPr` 不在最前面，Word 会忽略段落属性，导致：
- 表格单元格对齐方式丢失
- 文字错位
- 表格线位置错误

## 修复内容

### 修改文件
`backend/app/core/proofreadme/pipeline.py`

### 修改代码量
**仅 10 行代码**

### 具体修改

在 `_write_revision()` 函数中添加了 3 个步骤：

#### 1. 保存段落属性（第 177-179 行）
```python
# ── 【fix11】保存段落属性（w:pPr），确保它始终在最前面 ──────────
ns_w = "http://schemas.openxmlformats.org/wordprocessingml/2006/main"
ppr_elem = para_elem.find(f"{{{ns_w}}}pPr")
```

#### 2. 移除并重新插入到最前面（第 197-203 行）
```python
# ── 【fix11】确保 w:pPr 在段落最前面（Word XML 规范要求） ──────
if ppr_elem is not None:
    # 如果 w:pPr 存在，先移除再插入到最前面
    para_elem.remove(ppr_elem)
    para_elem.insert(0, ppr_elem)
    insert_index = 1  # run 节点从 w:pPr 之后开始
else:
    insert_index = 0
```

#### 3. 更新 Bug 修复记录（第 28 行）
```python
- [fix11] _write_revision 确保 w:pPr 始终在段落最前面，修复表格单元格对齐错位问题
```

## 技术细节

### Word OOXML 段落结构规范
根据 Office Open XML 规范（ISO/IEC 29500），段落元素的子元素必须按以下顺序出现：

1. `w:pPr` - 段落属性（可选，但如果存在必须在最前面）
2. `w:r` - 文字运行
3. `w:del` - 删除修订
4. `w:ins` - 插入修订
5. `w:hyperlink` - 超链接
6. 其他元素...

如果顺序错误，Word 会：
- 忽略错位的属性
- 使用默认格式
- 导致显示异常

### 段落属性（w:pPr）包含的内容
- `w:jc` - 对齐方式（左、中、右、两端对齐）
- `w:ind` - 缩进（首行缩进、左缩进、右缩进）
- `w:spacing` - 行距和段间距
- `w:pStyle` - 段落样式引用
- `w:numPr` - 编号属性
- 等等...

对于表格单元格，这些属性尤其重要，因为它们控制着单元格内文字的布局。

## 相关问题

### 为什么之前没有发现这个问题？
1. 正文段落通常 `w:pPr` 就在最前面，所以没有问题
2. 表格单元格的 `w:pPr` 可能在 run 节点之后（取决于文档创建方式）
3. 只有在修订写入时重新排列节点，才会暴露这个问题

### 这个修复会影响性能吗？
不会。只是增加了 2 次 DOM 操作（remove + insert），对性能影响可以忽略不计。

### 是否需要修改其他文件？
不需要。这是一个独立的修复，只涉及 `pipeline.py` 文件。
